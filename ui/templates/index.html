Any file matching the { files: [...], tree_sitter_analysis: [...] } shape from your scanner. Nothing leaves your browser — parsing happens locally. CFGs and call graphs are generated automatically from function source bodies when present.

Expected top-level shape
{
  "files": [ { "relative_path", "name", "extension",
               "language", "metadata": { "size", ... },
               "classes", "functions": [
                 { "name", "returns", "params",
                   "body",        // optional: source text, enables
                                  // CFG + call-graph generation
                   "calls": [],   // optional: explicit callee names
                   "cfg": {"nodes":[...], "edges":[...]}  // optional
                 }
               ], "structs", ... } ],
  "tree_sitter_analysis": [ { "file", "children",
               "has_error", "root_type" } ],
  "metadata": { "name", "file_count", "root" }
}

If a function has an explicit cfg, that's rendered as-is. Otherwise, if it has a body, a control-flow graph is derived heuristically by parsing if/for/while/return structure. The call graph is built the same way: explicit calls arrays are used when present, otherwise callee names are inferred from each function's body.
